= 将虚拟机从 VMware ESXi 迁移到 Red Hat OpenShift Virtualization
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
使用 Shift Toolkit 将虚拟机从 VMware ESXi 迁移到 Red Hat OpenShift Virtualization，方法是准备虚拟机、转换磁盘格式和配置目标环境。

Shift Toolkit 能够通过目标环境中的磁盘格式转换和网络重新配置，实现虚拟化平台之间的虚拟机迁移。



[[before-you-begin]]
== 开始之前

开始迁移之前，请确认满足以下先决条件。

.红帽 OpenShift 虚拟化要求
* 安装了以下运算符的 OpenShift 集群端点：
+
** OpenShift虚拟化操作员
** NetApp Trident CSI 驱动程序
** 新墨西哥州立大学


* NetApp Trident CSI 配置了适当的后端和存储类
* 已配置正确的 VLAN 的 NodeNetworkConfigurationPolicy 和 NetworkAttachmentDefinitions (NAD)
* OpenShift 集群可通过当前主机文件条目进行网络访问
* 集群管理员级别权限
* 已下载 Kubeconfig 文件


.VMware 要求
* VMDK 可以通过多种方式进行配置：所有 VMDK 都可以驻留在单个 NFSv3 卷上（无需存储 vMotion），每个 VMDK 都可以放置在自己的单个卷上，或者可以在卷内的 qtree 中组织多个 VMDK。
+

NOTE: Shift Toolkit 会自动检测布局并选择适当的克隆方法和 NAS 存储驱动程序。

+

NOTE: 当 VMDK 放置在 qtree 中时，Shift Toolkit 使用 ONTAP-NAS-economy 驱动程序。

* VMware 工具正在客户虚拟机上运行。
* 待迁移的虚拟机处于运行状态，以便进行准备。
* 必须先关闭虚拟机电源才能触发迁移
* VMware Tools 的移除将在虚拟机启动后在目标虚拟机管理程序上进行。


.Trident 技术诀窍和映射
* *ONTAP-NAS*：所有 VMDK 都可以驻留在单个卷上，或者每个 VMDK 都可以驻留在其自己的单个卷上。虚拟机选择可以在数据存储级别或虚拟机级别进行。
* *ONTAP-NAS-Economy*：VMDK 必须驻留在单个卷上，卷名必须遵守以下命名约定： `trident_qtree_pool_<storage-prefix>_<10 random characters>`。资源组中的 VM 选择仅在数据存储区级别。
+

NOTE: 对于 ONTAP-NAS-Economy，具有上述命名约定的卷必须预先存在，并且必须用作 VMware vCenter 上的数据存储。这意味着虚拟机应通过 Storage vMotioned 迁移到此特定数据存储区，或者应重命名现有数据存储区以匹配命名约定： `trident_qtree_pool_<storage-prefix>_<10 random characters>`。

+

NOTE: 对于 ONTAP-NAS-Economy，Trident 后端配置 (TBC) 应将参数 `Deny New Volume Pools`设置为 `true`。所使用的存储类还应将 storagePools 限制为 `tbc name: <aggr name where the trident_qtree_pool_<storage-prefix>_<10 random characters> resides>`。

+
.ONTAP-NAS-Economy 驱动程序的 TBC 配置示例
[%collapsible]
====
[source, yaml]
----
apiVersion: v1
kind: Secret
metadata:
	name: nas-eco-data-1172-secret
	namespace: trident
type: Opaque
stringData:
	username: <svm-admin-username>
	password: <svm-admin-password>
---
apiVersion: trident.netapp.io/v1
kind: TridentBackendConfig
metadata:
	name: nas-eco-data-1172
	namespace: trident
spec:
	backendName: nas-eco-data-1172
	credentials:
		name: nas-eco-data-1172-secret
	dataLIF: "192.168.1.100"
	denyNewVolumePools: "False"
	managementLIF: "192.168.1.50"
	storageDriverName: ontap-nas-economy
	svm: data_1172
	version: 1
----
====
+

NOTE: 参数  `denyNewVolumePools` 应在作为初始 PVC 创建的一部分创建  `trident_qtree_pool_<storage-prefix>_<10 random characters>` 之后立即设置为  `true`。将此值设置为  `true` 可确保 Trident 使用现有的 qtree 池来放置基于 qtree 的 PVC。

+
可以使用以下命令修补 TBC：

+
[source, bash]
----
oc patch tbc nas-eco-data-1172 -n trident --type=merge -p '{"spec":{"denyNewVolumePools":"true"}}'
----
+
.存储类的 YAML 示例
[%collapsible]
====
[source, yaml]
----
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
	name: nas-eco-data-1172
	annotations:
		storageclass.kubernetes.io/is-default-class: "true"
provisioner: csi.trident.netapp.io
parameters:
	backendType: ontap-nas-economy
	fsType: nfs
	storagePools: "nas-eco-data-1172:NSOL_NetApp_C800_T18U13_02_SSD_CAP_1"
allowVolumeExpansion: true
reclaimPolicy: Delete
volumeBindingMode: Immediate
----
====
* *ONTAP-SAN*：应使用 Storage vMotion 将 VMDK 放置在单个卷上（将 VMDK 模拟到 PVC/PV 构造）。虚拟机选择处于虚拟机级别。
* *ONTAP-SAN-Economy*：VMDK 必须驻留在单个 NFSv3 卷上，卷名必须遵守以下命名约定： `trident_lun_`。资源组中的 VM 选择仅在数据存储区级别。
+

NOTE: 对于 ONTAP-SAN-Economy，具有命名约定 `trident_lun_`的卷必须预先存在，并且必须用作 VMware vCenter 上的数据存储。这意味着虚拟机应通过 Storage vMotioned 迁移到此特定数据存储，或者应重命名现有数据存储以匹配命名约定 `trident_lun_`。

+
.ONTAP-SAN-Economy 的 TBC 配置示例
[%collapsible]
====
[source, yaml]
----
apiVersion: v1
kind: Secret
metadata:
	name: ontap-san800-eco-secret
	namespace: trident
type: Opaque
stringData:
	username: <svm-admin-username>
	password: <svm-admin-password>
---
apiVersion: trident.netapp.io/v1
kind: TridentBackendConfig
metadata:
	name: ontap-san800-eco
	namespace: trident
spec:
	backendName: ontap-san800-eco
	aggregate: NSOL_NetApp_C800_T18U13_01_SSD_CAP_1
	credentials:
		name: ontap-san800-eco-secret
	dataLIF: "192.168.1.110"
	defaults:
		protocol: iSCSI
		snapshotPolicy: none
		spaceAllocate: "true"
		spaceReserve: none
		tieringPolicy: none
	managementLIF: "192.168.1.60"
	storage:
		- labels:
			backend: san800-eco
	storageDriverName: ontap-san-economy
	svm: data_1172
	version: 1
----
====
+
.ONTAP-SAN-Economy 的示例存储类配置
[%collapsible]
====
[source, yaml]
----
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
	name: sc-ontap-san-eco
provisioner: csi.trident.netapp.io
parameters:
	backendType: ontap-san-economy
	selector: "backend=san800-eco"
allowVolumeExpansion: true
reclaimPolicy: Delete
volumeBindingMode: Immediate
----
====
+

NOTE: 对于 ONTAP-SAN 和 ONTAP-SAN-Economy，应先将虚拟机从任何基于块的数据存储通过存储 vMotioned 迁移到 ONTAP NFSv3 卷。然后，Shift Toolkit 会将 VMDK 转换为 LUN，并将其作为 PVC 导入到相应的命名空间。



资源组的虚拟机选择可以是虚拟机级别的，也可以是数据存储级别的。根据所选内容，工作流将选择适当的 ONTAP NAS 或 SAN 存储驱动程序。例如，如果选择了单个 VM，则使用 ONTAP-NAS 驱动程序。如果多个 VMDK 驻留在同一个卷上，则会根据源卷及其 SVM 以及在 OpenShift 端配置的 TBC 和存储类使用 ONTAP-NAS 或 ONTAP-NAS-Economy 驱动程序。

.客户机虚拟机要求
* 对于 Windows 虚拟机：使用本地管理员凭据
* 对于 Linux 虚拟机：使用具有执行 sudo 命令而无需密码提示权限的用户
* 对于 Windows 虚拟机：将 VirtIO ISO 挂载到虚拟机（从 [此处应填写下载链接] 下载）。link:https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/archive-virtio/virtio-win-0.1.271-1/virtio-win-0.1.271.iso["此处"] ）
+

NOTE: 准备脚本使用 .msi 包来安装驱动程序和 qemu-guest-agents。

[[step-4-execute-the-migration]]
== 步骤 4：执行迁移

触发迁移工作流，将虚拟机从 VMware ESXi 转换为 OpenShift Virtualization。

.开始之前
所有虚拟机均按照计划的维护时间表正常关机。

.步骤
. 在蓝图上，单击“迁移”。
+
.显示示例
[%collapsible]
====
image::shift-toolkit-114.png[迁移步骤]

====
. Shift Toolkit 执行以下步骤：
+
** 删除蓝图中所有虚拟机的现有快照
** 触发源虚拟机快照
** 在磁盘转换之前触发卷快照
** 克隆各个卷
** 将每个 VMDK 的 VMDK 格式转换为 RAW 格式
+
Shift Toolkit 会自动查找与每个虚拟机关联的所有 VMDK，包括主启动磁盘。






NOTE: 如果存在多个 VMDK 文件，每个 VMDK 都将根据所使用的存储驱动程序进行转换并放入其自己的 PVC 中。

* 清理卷，使其仅保留 disk.img 文件
+
将虚拟机磁盘映像转换为 RAW 格式后，Shift Toolkit 会清理卷，将原始文件重命名为 disk.img，并分配必要的权限。

* 使用Trident导入功能以 PVC 格式导入销量。
+
然后使用NetApp Trident API 将卷作为 PVC 导入。

* 使用虚拟机特定的 YAML 文件创建虚拟机
+
PVC 导入完毕且 PV 就位后，Shift Toolkit 使用 OC CLI 根据操作系统使用 yaml 文件创建每个虚拟机。




NOTE: 虚拟机在“默认”命名空间下创建。

* 在目标位置启动虚拟机
+
根据虚拟机操作系统，Shift Toolkit 会自动分配虚拟机启动选项以及存储控制器接口。对于 Linux 发行版，使用 VirtIO 或 VirtIO SCSI。对于 Windows 系统，虚拟机启动时使用 SATA 接口，然后计划脚本会自动安装 VirtIO 驱动程序并将接口更改为 VirtIO。

* 在每个虚拟机上注册网络
+
网络是根据蓝图选择进行分配的。

* 使用 cron 作业移除 VMware Tools 并分配 IP 地址

[[use-migration-toolkit-for-virtualization-with-shift-toolkit-scripted-approach]]
== 将 Migration Toolkit for Virtualization 与 Shift Toolkit 结合使用（脚本化方法）

本节介绍如何使用NetApp Shift Toolkit 和 Migration Toolkit for Virtualization (MTV) 实现向 Red Hat OpenShift Virtualization 的无缝迁移。

.开始之前
确保满足以下先决条件：

* 已安装 OpenShift Virtualization Operator 和NetApp Trident CSI 驱动程序的 OpenShift 集群
* MTV 2.9.4（包含转换模式）
* link:https://mysupport.netapp.com/site/tools/tool-eula/netapp-shift-toolkit["Shift 工具包"]已安装
+

NOTE: 由于仅使用 Shift Toolkit API，因此无需配置 Shift Toolkit 资源组或蓝图。

* 在 OpenShift 集群上拥有管理员级别权限
* 安装了 OC 命令行工具的 Linux 实例
+
** 已导出 Kubeconfig 或执行 OC 登录以连接到集群
** 从 Shift Toolkit UI 下载名为 "Shift-VM-to-OpenShift-MTV" 的脚本（*Settings > Developer Access > Script Blocker*）
** 解压缩文件： `unzip Shift-VM-to-OpenShift-MTV.zip`
** 请确保已安装 Python3： `dnf install python3`
** 安装 OpenJDK 8 或更高版本： `yum install java-1.8.0-openjdk`
** 安装要求： `pip install -r requirements.txt`


* *MTV 的虚拟机要求*：VMDK 可以以不同的方式组织：它们可以全部放置在单个卷中（无需存储 vMotion），单独分配给单独的卷，或者在 NFS 卷内的 qtree 中组合在一起。该脚本会自动检测布局，并根据 TBC UUID 选择适当的克隆方法和 NAS 存储驱动程序。


.步骤
. 使用 MTV 创建迁移计划。
+
为了利用快速 VMDK 转换，请为虚拟机创建迁移计划，并确保 YAML 文件中包含以下参数：

+
** `targetNamespace: default`
** `type: conversion`
** `storage: {}`
+

NOTE: 应事先制定计划，以确保 MTV 配置的 IP 设置得到保留。



. 将 vCenter 中的虚拟机和ONTAP存储上的卷进行映射。
+
使用脚本创建必要的 PVC 并将其导入到 OpenShift 集群。  PVC必须带有以下标签和注释：

+
*标签：*

+
** PVC 中的 vmID 和 vmUUID（叉车会查找这些值）
+
*注解：*

** vmdk 磁盘名称 `forklift.konveyor.io/disk-source`
+
该脚本确保为每个PVC设置这些属性，并更新disk.img的权限：

** `"owner": { "id": 107 }`
** `"group": { "id": 107 }`
** `"mode": "0655"`


. 请使用以下详细信息更新 JSON 文件：
+
** * ONTAP集群*：可以是 SVM；可以使用 vsadmin。如果克隆卷不需要立即分离，请将 splitclone 设置为“False”。
** *vCenter*：发现虚拟机及其关联 VMDK 文件的最低 RBAC 权限
** * Trident存储类*：应为 NFS 后端，且 YAML 文件中版本信息正确。
** *OpenShift*：指定项目名称（默认值仅用作示例）
+

NOTE: 其余值保持默认值。



. 满足先决条件后，执行 `python3 main.py`创建 PVC 并将其导入到 OpenShift 集群。
. PVC 导入后，使用 MTV 触发迁移，以创建具有相应规范的 VM。
