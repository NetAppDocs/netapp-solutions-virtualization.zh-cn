= 使用 SnapMirror Active Sync（SAN 和 NAS）为 VCF 管理域配置延伸集群
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
在此用例中，我们概述了使用ONTAP tools for VMware vSphere为 VCF 管理域配置延伸集群的过程。此过程包括部署 vSphere 主机和 vCenter Server、安装ONTAP工具、使用SnapMirror Active Sync 保护数据存储库、将虚拟机迁移到受保护的数据存储库以及配置补充存储。

image:vmw-vcf-vmsc-mgmt-smas-001.png["使用ONTAP为 VCF 管理域延伸集群"]

SAN 支持均匀和非均匀延伸集群配置。对于 NAS，它是使用 ONTAP 9.19.1 的主动-被动配置。

[NOTE]
====
主机邻近度设置与多路径配置一起使用，以确保为存储流量选择最佳路径。如果是 SCSI，则在 igroup 上配置主机邻近度设置；如果是 NVMe-oF，则在子系统上配置主机邻近度设置。例如，在统一主机访问配置中，主机可以访问扩展群集中的两个存储系统。在多路径配置中，根据主机邻近度设置配置最佳和非最佳路径。

====


[[scenario-overview]]
== 场景概述

拉伸集群解决方案可以在默认集群上实施，也可以在 VCF 管理或工作负载域中的其他集群上实施。ONTAP tools 10.6 支持在 iSCSI 和 FC 协议上对 VMFS 数据存储进行 SnapMirror 主动同步的数据存储保护。ONTAP 支持 SAN（带 iSCSI、FC、NVMe-oF）和 NAS（NFS v3 和 NFSv4.1）的 SnapMirror 主动同步。对于 SAN 协议，保护在一致性组级别执行，而对于 NAS，保护在 SVM 级别执行。下图说明了使用适用于带 FC 的 VMFS 的 ONTAP tools for VMware vSphere 的 VCF 管理域的延伸集群解决方案。

image:vmware-vcf-asa-mgmt-stretchcluster-002.png["使用ONTAP为 VCF 管理域延伸集群"]

.管理域上的主体存储
[%collapsible%open]
====
. 使用任何支持的协议部署 VCF 管理域。
+
.. 对于FC和NFSv3上的VMFS，直接使用VCF安装程序工具。如果是iSCSI、NVMe-oF和NFSv4.1，则需要先使用 vCenter 进行设置，然后使用VCF安装程序工具部署管理域。如需了解更多信息，请参阅 link:vmw-vcf-migrate.html["使用 iSCSI、NVMe-oF 和 NFSv4.1 的 VCF 管理域部署"]


. ONTAP tools for VMware vSphere
. 为 VMware vSphere 部署SnapCenter插件（可选）
. 保护数据存储库。
+
.. 对于 iSCSI 和 FC，使用 ONTAP tools 10.6 或更高版本来保护数据存储区。对于 NVMe-oF 和 NFSv4.1，请使用系统管理器来保护数据存储区。如需参考，请查看下面的 NVMe/TCP 和 NFS 视频演示。




====
.管理域上的补充存储
[%collapsible%open]
====
管理域启动并运行后，可以使用 ONTAP tools 10.6 或更高版本创建其他数据存储，并通过 iSCSI 和 FC 的 SnapMirror 活动同步进行保护。对于 NVMe-oF 和 NFS，请查看以下视频演示以供参考，因为演示是在工作负载域上执行的，但管理域也可以遵循相同的步骤。
