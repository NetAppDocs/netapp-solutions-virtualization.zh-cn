= 使用 ONTAP 上的 NFS 数据存储库作为 VCF 工作负载域的主存储
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
在此用例中，我们概述了将 ONTAP 上的 NFS 数据存储配置为 VMware Cloud Foundation (VCF) 工作负载域的主存储解决方案的过程。此过程总结了所需的组件、配置步骤和部署过程。



[[benefits-of-nfs]]
== NFS 的优势

*简单易用：*NFS 设置和管理简单，使其成为需要快速简便的文件共享环境的绝佳选择。

*可扩展性*：ONTAP 的架构允许 NFS 有效扩展，从而无需对基础架构进行重大更改即可支持不断增长的数据需求。

*灵活性*：NFS 支持广泛的应用程序和工作负载，使其适用于各种用例，包括虚拟化环境。



[[scenario-overview]]
== 场景概述

此场景涵盖以下高级步骤：

* 为 NFS 流量创建具有逻辑接口 (LIF) 的存储虚拟机 (SVM)
* 验证ONTAP存储虚拟机 (SVM) 的网络以及是否存在用于承载 NFS 流量的逻辑接口 (LIF)。
* 创建导出策略以允许 vSphere 主机访问 NFS 卷。
* 在ONTAP存储系统上创建 NFS 卷。
* 在 SDDC Manager 中为 NFS 和 vMotion 流量创建网络池。
* 在 vCenter 中为 VCF 工作负载域调试主机。
* 使用 NFS 数据存储作为主存储在 VCF Ops 中部署 VCF 工作负载域。
* 确保集群映像包含适用于 VMware VAAI 的 NetApp NFS 插件。



NOTE: 此解决方案适用于支持 NFS 存储的 ONTAP 平台，包括 NetApp AFF、AFX 和 FAS。



[[prerequisites]]
== 前提条件

此场景中使用以下组件和配置：

* NetApp AFF、AFX 或 FAS 存储系统，其中 Storage Virtual Machine (SVM) 已配置为允许 NFS 流量。
* 已在 IP 网络上创建用于承载 NFS 流量并与 SVM 关联的逻辑接口 (LIF)。
* VCF 管理域部署已完成，且可访问 VCF Operations Manager 界面。
* 至少 2 台 vSphere 主机已配置为在 VCF 管理网络上进行通信。
* 为此目的建立的 VLAN 或网络段上为 vMotion 和 NFS 存储流量保留的 IP 地址。



NOTE: 部署 VCF 工作负载域时，VCF 会验证与 NFS 服务器的连接。这是在使用 NFS IP 地址添加任何其他 vmkernel 适配器之前，使用 vSphere 主机上的管理适配器完成的。因此，有必要确保以下两点之一：1）管理网络可路由到 NFS 服务器，或 2）管理网络的 LIF 已添加到托管 NFS 数据存储卷的 SVM，以确保验证可以继续。

有关配置ONTAP存储系统的信息，请参阅link:https://docs.netapp.com/us-en/ontap["ONTAP 9 文档"]中心。

有关配置 VCF 的信息，请参阅 link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1.html["VMware 云基础文档"]。

有关在 vSphere 群集中使用 NFS 的更多信息，请参阅link:vmw-vvf-overview.html["适用于 vSphere 8 的 NFS v3 参考指南"]。

[[deployment-steps]]
== 部署步骤

要部署以 NFSv3 数据存储区为主存储的 VCF 工作负载域，请完成以下步骤：

.验证ONTAP SVM 的网络连接
[%collapsible%open]
====
验证是否已为在 ONTAP 存储集群和工作负载域之间传输 NFS 流量的网络建立所需的逻辑接口。

. 从 ONTAP System Manager 导航到左侧菜单中的 *Storage VMs*，然后单击要用于 NFS 流量的 SVM。在 *Overview* 选项卡上的 *Network interfaces* 下，单击 *NFS* 标签上方的数字。在列表中验证是否列出了所需的 LIF IP 地址。
+
image:vmw-vcf-viwld-principal-nfs-001.png["验证 SVM 的 NFS LIF"]



或者，使用以下命令从ONTAP CLI 验证与 SVM 关联的 LIF：

[source, cli]
----
network interface show -vserver <SVM_NAME>
----
. 验证 vSphere 主机是否可以与 ONTAP NFS 服务器通信。通过 SSH 登录 vSphere 主机并 ping SVM LIF：


[source, cli]
----
vmkping <IP Address>
----

NOTE: 部署工作负载域时，VCF 会验证与 NFS 服务器的连接。这是在使用 NFS IP 地址添加任何其他 vmkernel 适配器之前，使用 vSphere 主机上的管理适配器完成的。因此，有必要确保满足以下条件之一：1）管理网络可路由到 NFS 服务器，或 2）管理网络的 LIF 已添加到托管 NFS 数据存储卷的 SVM，以确保验证可以继续进行。

====
.创建共享 NFS 卷的导出策略
[%collapsible%open]
====
在ONTAP系统管理器中创建导出策略来定义 NFS 卷的访问控制。

. 在ONTAP系统管理器中，单击左侧菜单中的 *存储虚拟机*，然后从列表中选择一个 SVM。
. 在*设置*选项卡上找到*导出策略*并单击箭头进行访问。
+
image:vmw-vcf-viwld-principal-nfs-002.png["访问出口政策"]

+
{nbsp}

. 单击添加后，将打开*新导出策略*窗口。添加策略的名称，单击*添加新规则*按钮，然后单击*+添加*按钮以开始添加新规则。
+
image:vmw-vcf-viwld-principal-nfs-003.png["新的出口政策"]

+
{nbsp}

. 填写要包含在规则中的 IP 地址、IP 地址范围或网络。取消选中 *SMB/CIFS* 和 *FlexCache* 框，然后选择以下访问详细信息。选择 UNIX 框足以进行 vSphere 主机访问。
+
image:vmw-vcf-viwld-principal-nfs-004.png["保存新规则"]

+

NOTE: 部署工作负载域时，VCF 会验证与 NFS 服务器的连接。此操作在使用 NFS IP 地址添加任何其他 vmkernel 适配器之前，通过 vSphere 主机上的管理适配器完成。因此，必须确保导出策略包含 VCF 管理网络，以便验证能够继续进行。

. 输入所有规则后，单击“保存”按钮保存新的导出策略。
. 或者，您可以在ONTAP CLI 中创建导出策略和规则。请参阅ONTAP文档中创建导出策略和添加规则的步骤。
+
** 使用ONTAP CLIlink:https://docs.netapp.com/us-en/ontap/nfs-config/create-export-policy-task.html["创建导出策略"] 。
** 使用ONTAP CLIlink:https://docs.netapp.com/us-en/ontap/nfs-config/add-rule-export-policy-task.html["向导出策略添加规则"] 。




====
.创建 NFS 卷
[%collapsible%open]
====
在ONTAP存储系统上创建一个 NFS 卷，用作工作负载域部署中的数据存储。

. 从ONTAP系统管理器导航到左侧菜单中的 *存储 > 卷*，然后单击 *+添加* 以创建新卷。
+
image:vmw-vcf-viwld-principal-nfs-005.png["添加新卷"]

+
{nbsp}

. 添加卷的名称，填写所需的容量并选择将托管该卷的存储虚拟机。单击“*更多选项*”继续。
+
image:vmw-vcf-viwld-principal-nfs-006.png["添加卷详细信息"]

+
{nbsp}

. 在访问权限下，选择导出策略，其中包括 VCF 管理网络或 IP 地址和 NFS 网络 IP 地址，这些地址将用于验证 NFS 服务器和 NFS 流量。
+
image:vmw-vcf-viwld-principal-nfs-007.png["添加卷详细信息"]

+
+ {nbsp}

+

NOTE: 部署 VCF 工作负载域时，VCF 会验证与 NFS 服务器的连接。这是在使用 NFS IP 地址添加任何其他 vmkernel 适配器之前，使用 vSphere 主机上的管理适配器完成的。因此，有必要确保以下两点之一：1）管理网络可路由到 NFS 服务器，或 2）管理网络的 LIF 已添加到托管 NFS 数据存储卷的 SVM，以确保验证可以继续。

. 或者，可以在 ONTAP CLI 中创建 NFS 卷。有关详细信息，请参阅 ONTAP 命令文档中的 link:https://docs.netapp.com/us-en/ontap-cli/volume-create.html["volume create"] 命令。


====


[[vcf-workload-domain-default-cluster]]
=== VCF 工作负载域 - 默认集群

管理域启动并运行后，可以创建 VCF 工作负载域：

* 使用 VCF Ops UI。vSphere 主机在 vCenter 中调试完毕，并配置网络池。使用 System Manager 或 ONTAP API 将 NFS 卷导出到 vSphere 主机。
* 将现有 vSphere 环境作为新工作负载域导入。ONTAP tools for VMware vSphere 或 System Manager 或 ONTAP API 可用于将 NFSv3 或 NFS4.1 数据存储部署到 vSphere 集群。




[[vcf-workload-domain-additional-cluster]]
=== VCF 工作负载域 - 附加集群

要使用其他群集扩展工作负载域，请参阅 https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/building-your-private-cloud-infrastructure/working-with-workload-domains/expand-a-workload-domain/add-a-cluster-to-a-workload-domain-using-the-sddc-manager-ui.html["向 VCF 域添加 SDDC 集群"]。

在高级别上，向工作负载域添加其他集群的步骤如下：* 确保主机已调试完毕，并在 vCenter 中配置了网络池。* NFS 卷在 ONTAP 存储系统上进行配置，并导出到附加集群中的主机。* NFS 卷挂载到附加集群中的一个 vSphere 主机上。* 在 vCenter 上的工作负载域中创建新的 SDDC 集群，然后按照向导将附加集群添加到工作负载域。
