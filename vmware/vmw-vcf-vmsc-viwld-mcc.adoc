= 使用 MetroCluster 为 VCF 工作负载域配置延伸集群

:nofooter:

:linkattrs:

[role="lead"]
在此用例中，我们概述了使用 ONTAP MetroCluster 与 FC 或 iSCSI 或 NVMe-oF 或 NFSv3 或 NFSv4.1 作为主数据存储区，为 VMware Cloud Foundation (VCF) 工作负载域配置延伸集群的过程。VCF 根据您的需求提供灵活的部署选项。VCF Ops 工具用于部署新的 VCF 工作负载域，或将现有 vSphere 环境导入 VCF 工作负载域。在本文档中，我们将重点介绍 MetroCluster 部分，并根据部署步骤指向其他相关文档。

image:vmw-vcf-vmsc-viwld-mcc-001.png["采用 vMSC 的 VCF 工作负载域，宽度=500"]



[[introduction]]
== 简介

在此解决方案中，我们将演示如何使用 ONTAP MetroCluster 作为主体数据存储实现 Stretched VCF Workload Domain。MetroCluster 允许为 ONTAP 集群上运行的所有工作负载部署高可用性解决方案。如果需要部署特定于工作负载的高可用性解决方案，请考虑使用 SnapMirror 活动同步（SAN 和 NAS）。SnapMirror 活动同步（SAN）在一致性组级别工作，而 SnapMirror 活动同步（NAS）在 SVM 级别工作。有关详细信息，请参阅 link:vmw-vcf-vmsc-viwld-smas.html["使用 SnapMirror Active Sync（SAN 和 NAS）为 VCF 工作负载域配置延伸集群"]。



[[prerequisites]]
== 前提条件

此场景需要以下组件和配置：

* 支持的ONTAP MetroCluster配置
* 使用首选存储协议配置的 Storage Virtual Machine (SVM)。
* 已创建逻辑接口 (LIF) 以承载存储流量，并与 SVM 相关联。




[[high-level-overview]]
== 高级概述

MetroCluster 为聚合级别处理的工作负载提供高可用性解决方案。SVM 将在 MetroCluster 中的一个故障域上处于活动状态。

[[deployment-steps-for-greenfield-vcf-workload-domain-with-metrocluster]]
== 使用 MetroCluster 的 Greenfield VCF 工作负载域的部署步骤

对于 Greenfield 部署（没有任何现有 VCF 组件的新部署），使用 VCF Ops 工具来部署工作负载域。此方案支持 FC 上的 VMFS 和 NFSv3。

如果是 FC 上的 VMFS，请参见link:vmw-vcf-viwld-principal-fc.html["基于 FC 的 VMFS 数据存储区位于 ONTAP 上作为主存储的 VCF 工作负载域"]以获取更多信息。对于 NFSv3，请参见link:vmw-vcf-viwld-principal-nfs.html["以 NFSv3 数据存储为主存储的 ONTAP 上的 VCF 工作负载域"]以获取更多信息。



[[deployment-steps-for-brownfield-vcf-workload-domain-with-metrocluster]]
== 适用于 Brownfield VCF 工作负载域与 MetroCluster 的部署步骤

棕地部署是指您拥有现有 vSphere 环境并希望将其作为 VCF 工作负载域导入的方案。

对于 iSCSI、NVMe-oF 和 NFSv4.1，需要使用 vCenter（最好使用 ONTAP tools）进行设置，然后使用 VCF Ops tool 将其导入为工作负载域。如需了解更多信息，请参阅 link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/building-your-private-cloud-infrastructure/working-with-workload-domains/import-an-existing-vcenter-to-create-a-workload-domain.html["导入现有 vCenter 以创建工作负载域"]。
