= 使用MetroCluster为 VCF 管理域配置延伸集群
:hardbreaks:

:nofooter: 
:icons: font
:linkattrs:

[role="lead"]
在此用例中，我们概述了使用 ONTAP MetroCluster 与 FC 或 iSCSI 或 NVMe-oF 或 NFSv3 或 NFSv4.1 作为主数据存储区为 VMware Cloud Foundation (VCF) 管理域配置延伸集群的过程。VCF 根据您的需求提供灵活的部署选项。VCF Installer 工具用于部署新的 VCF 管理域或将现有 vSphere 环境转换为 VCF 管理域。在本文档中，我们将重点介绍 MetroCluster 部分，并根据部署步骤指向其他文档。

image:vmw-vcf-vmsc-mgmt-mcc-001.png["带有 vMSC 的 VCF 管理域,宽度=500"]



[[introduction]]
== 简介

在此解决方案中，我们将演示如何使用 ONTAP MetroCluster 作为主体数据存储实现 Stretched VCF Management Domain。MetroCluster 允许为 ONTAP 集群上运行的所有工作负载部署高可用性解决方案。如果需要部署特定于工作负载的高可用性解决方案，请考虑使用 SnapMirror 活动同步（SAN 和 NAS）。SnapMirror 活动同步（SAN）在一致性组级别工作，而 SnapMirror 活动同步（NAS）在 SVM 级别工作。有关详细信息，请参阅 link:vmw-vcf-vmsc-mgmt-smas.html["使用 SnapMirror Active Sync（SAN 和 NAS）为 VCF 管理域配置延伸集群"]。



[[prerequisites]]
== 前提条件

此场景需要以下组件和配置：

* 支持的ONTAP MetroCluster配置
* 使用首选存储协议配置的 Storage Virtual Machine (SVM)。
* 已创建逻辑接口 (LIF) 以承载存储流量，并与 SVM 相关联。

== 高级概述

MetroCluster 为聚合级别处理的工作负载提供高可用性解决方案。SVM 将在 MetroCluster 中的一个故障域上处于活动状态。

[[deployment-steps-for-greenfield-vcf-management-domain-with-metrocluster]]
== Greenfield VCF 管理域与 MetroCluster 的部署步骤

对于 Greenfield 部署（没有任何现有 VCF 组件的新部署），使用 VCF Installer 工具来部署管理域。此方案支持 FC 上的 VMFS 和 NFSv3。

如果是 FC 上的 VMFS，请参见link:vmw-vcf-mgmt-principal-fc.html["以 FC 为基础的 VMFS 数据存储区（位于 ONTAP 上）作为主存储的 VCF 管理域"]以获取更多信息。对于 NFSv3，请参见link:vmw-vcf-mgmt-principal-nfs.html["以 ONTAP 上的 NFSv3 数据存储为主存储的 VCF 管理域"]以获取更多信息。



[[deployment-steps-for-brownfield-vcf-management-domain-with-metrocluster]]
== 采用 MetroCluster 的棕地 VCF 管理域部署步骤

棕地部署是一种场景，其中您已有现有的 vSphere 环境，并希望将其融合为 VCF 管理域。

对于 iSCSI、NVMe-oF 和 NFSv4.1，需要使用 vCenter（最好使用 ONTAP tools）进行设置，然后使用 VCF 安装程序工具收敛到管理域。如需了解更多信息，请参阅 link:vmw-vcf-mgmt-vmfs.html["vCenter 与 VMFS 数据存储的融合"] 和 link:vmw-vcf-mgmt-nfs.html["vCenter 与 NFS 数据存储的融合"]。
