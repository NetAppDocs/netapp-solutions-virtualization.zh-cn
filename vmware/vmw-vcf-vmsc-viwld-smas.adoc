= 使用 SnapMirror 活动同步（SAN 和 NAS）为工作负载域配置延伸集群
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
在此用例中，我们概述了使用 SnapMirror active sync 以及 ONTAP tools for VMware vSphere（ONTAP tools 10.6 支持 FC 和 iSCSI）为工作负载域配置延伸集群的步骤。ONTAP 支持针对 SAN（使用 iSCSI、Fibre Channel 和 NVMe over Fabrics）和 NAS（NFSv3 和 NFSv4.1）的 SnapMirror active sync。

image:vmw-vcf-vmsc-viwld-smas-001.png["使用 SnapMirror 主动同步的 VCF 延伸集群"]

SAN 支持均匀和非均匀延伸集群配置。对于 NAS，它是使用 ONTAP 9.19.1 的主动-被动配置。

[NOTE]
====
主机邻近度设置与多路径配置一起使用，以确保为存储流量选择最佳路径。如果是 SCSI，则在 igroup 上配置主机邻近度设置；如果是 NVMe-oF，则在子系统上配置主机邻近度设置。例如，在统一主机访问配置中，主机可以访问扩展群集中的两个存储系统。在多路径配置中，根据主机邻近度设置配置最佳和非最佳路径。

====


[[scenario-overview]]
== 场景概述

VCF 工作负载域上的数据存储区可以通过 SnapMirror 主动同步进行保护，以提供延伸集群解决方案。保护在 SAN 的数据存储级别（一致性组）启用，并在 NAS 的 SVM 级别受到保护。



[[prerequisites]]
== 前提条件

.工作负载域上的主存储
[%collapsible%open]
====
工作负载域可以通过导入或使用 VCF Ops 工具创建。

. 使用任何支持的协议创建工作负载域。
. link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/configure/add-vcenter.html["将工作负载域 vCenter 注册到ONTAP工具管理器以部署 vCenter 插件"]
. link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/configure/add-storage-backend.html["在ONTAP工具上注册存储系统"]
. 对于 iSCSI 和 FC 数据存储，请参阅 link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/protect/protect-multiple-ds.html["使用 ONTAP 工具保护 vSphere 数据存储库"]
. 对于 NVMe-oF 和 NFS 数据存储区，请查看下面的视频演示，了解使用 SnapMirror 活动同步保护工作负载域上数据存储区的步骤。


====
.工作负载域上的补充存储
[%collapsible%open]
====
工作负载域启动并运行后，可以使用 ONTAP tools 创建和保护其他数据存储区。有关 SnapMirror 活动同步的更多详细信息，请参阅 https://docs.netapp.com/us-en/ontap/snapmirror-active-sync/index.html#benefits["了解 ONTAP SnapMirror 活动同步"]


TIP: 使用 ONTAP tools 10.6 及更高版本，您可以使用 SnapMirror 活动同步保护工作负载域上的数据存储区。请参阅下面的视频演示，了解使用 SnapMirror 活动同步保护工作负载域上数据存储区的步骤。
